# 研究结论：数据新鲜度与复权价差修复

## 当前观测

2026-07-14 运行 live gate 的当前阻断项：

- `trading_calendar_coverage`：交易日历只到 `2026-07-02`，未覆盖 `2026-07-14`。
- `qmt_akshare_price_diff`：近期窗口中 QMT/AKShare 后复权价差超过 2% 的样本为 `70177` 行，占 `5.4079%`。

当前关键数据日期：

| 数据集 | 最新日期 | 备注 |
|---|---|---|
| 未复权日线 | 2026-07-02 | QMT 主源，落后 |
| 后复权日线 | 2026-07-08 | QMT 主源，晚于未复权 |
| AKShare 对照 | 2026-07-09 | 晚于 QMT 未复权和日历 |
| 交易日历 | 2026-07-02 | live gate 阻断 |
| 执行股票池 | 2026-07-02 | 与未复权同日，但落后当前评估日 |

## 决策 1：以共同交易日作为 live-ready 日期

**Decision**: live-ready 的 `latest_trade_date` 取核心数据集共同最新日期，而不是任一数据集的最大日期。

**理由**: 实盘信号同时依赖日线、执行股票池和交易日历。只要一个核心表落后，就可能产生不可交易或日期错配的信号。

**替代方案**: 允许部分数据晚于或早于其他数据。拒绝原因：会掩盖数据不一致，尤其是 AKShare 晚于 QMT 时容易误判可用日期。

## 决策 2：复权价差先诊断，不直接覆盖

**Decision**: QMT 后复权价仍作为策略收益主口径；AKShare 用作交叉校验。价差超过阈值时先生成诊断报告，不直接用 AKShare 覆盖 QMT。

**理由**: QMT `back_ratio` 与 AKShare `close_hfq` 可能存在复权基准、单位、精度、停牌补齐、除权日处理差异。直接覆盖会让历史回测口径突变。

**替代方案**: 简单提高阈值或关闭校验。拒绝原因：会把真实异常混入 live-ready 数据。

## 决策 3：近期窗口优先，全历史辅助

**Decision**: live gate 默认检查最近 252 个交易日；诊断 CLI 可输出全历史扩展报告。

**理由**: 实盘前最关注当前可交易窗口；全历史早期数据缺口不应阻塞今日实盘，但需要在研究报告中说明。

## 决策 4：失败隔离优先于半更新

**Decision**: 任一拉取、合并、校验失败都写入 `data/quarantine/`，不得更新 `silver/gold`。

**理由**: 半更新比不更新更危险。旧数据至少会被 freshness gate 阻断，半更新可能让部分检查误通过。

## 待确认风险

- QMT 网关当前是否能稳定返回 2026-07-14 前最近交易日数据。
- AKShare `close_hfq` 与 QMT `back_ratio` 的复权基准是否可线性对齐。
- 执行股票池是否应由 `daily_status` 重新生成，还是复用现有 `pit_universe` 构建流程。
