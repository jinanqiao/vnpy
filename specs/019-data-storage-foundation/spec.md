# 功能规格：数据存储底座改造

**功能分支**：`019-data-storage-foundation`

**创建日期**：2026-07-14

**状态**：草稿

**输入描述**：用户要求“按 SDD 为刚刚上下文聊到的数据库搭建改造创建 spec 计划，不写代码”

## 用户场景与测试 *(必填)*

### 用户故事 1 - 生成信号前确认数据可信 (优先级：P1)

作为量化系统操作者，我需要一个统一的数据就绪状态视图，告诉我当前本地数据是否适合研究、回测、模拟交易或实盘信号生成，避免过期、不完整或不一致的数据悄悄进入交易决策。

**为什么是这个优先级**：数据是一切策略的基础。一个可实盘系统必须在数据过期或质量不合格时默认阻断，而不是继续运行。

**独立测试方式**：可以用现有 `data/` 目录运行规划中的数据就绪检查流程，确认它能报告最新交易日、数据源覆盖率、质量状态和阻断原因，不依赖真实下单代码。

**验收场景**：

1. **假设** 本地存在 QMT 和 AKShare 数据文件，**当** 以实盘模式评估数据就绪状态，**那么** 系统能识别最新可用交易日，并根据数据门禁规则判断它是否可用于实盘信号生成。
2. **假设** 任一必需的 gold 层数据缺失、过期、重复，或阻断级跨数据源校验不通过，**当** 以实盘模式评估数据就绪状态，**那么** 结果必须阻断，并给出具体数据集、检查项和原因。
3. **假设** 某份数据适合研究但不适合实盘，**当** 输出状态报告，**那么** 报告必须区分“研究可用”“回测可用”“模拟可用”和“实盘可用”。

---

### 用户故事 2 - 每次信号都能追溯到数据版本 (优先级：P2)

作为研究者或系统操作者，我需要每次信号和回测运行都引用一个不可变的数据版本，这样后续才能复现结果，并审计当时使用了哪些源文件、质量检查结果和转换产物。

**为什么是这个优先级**：如果没有版本化 manifest 和运行元数据，一次表现很好或很差的回测，在数据文件变化后就无法解释。

**独立测试方式**：可以基于现有数据文件创建一个规划中的数据版本记录，并确认一次信号运行可以引用这个版本，而不需要复制底层 parquet 大文件。

**验收场景**：

1. **假设** 新一轮数据构建完成，**当** manifest 被固化，**那么** 它必须记录源文件路径、行数、日期范围、内容哈希、数据源名称、质量检查结果和构建时间。
2. **假设** 一次信号运行产出，**当** 查看它的元数据，**那么** 它必须且只能引用一个数据版本，并能说明该信号使用了哪些策略输入数据。
3. **假设** 历史 manifest 已存在，**当** 操作者查询某次历史运行，**那么** 系统可以定位那次运行使用的精确数据状态。

---

### 用户故事 3 - 不把所有大数据搬进传统数据库，也能像数据库一样查询 (优先级：P3)

作为策略开发者，我需要通过轻量查询层对本地 parquet 数据做 SQL 风格查询，同时继续把大规模行情数据保存在 parquet 文件里，这样在 100G 本地空间预算下，分析仍然快速、可复现且节省存储。

**为什么是这个优先级**：当前数据规模和工作流更适合文件型数据湖，而不是重型数据库迁移。DuckDB 这类查询层可以带来数据库式体验，同时不增加不必要的运维负担。

**独立测试方式**：可以通过查询合同定义，让查询层读取现有 parquet 表，并返回日线、可交易股票池、manifest 和质量结果的预期记录。

**验收场景**：

1. **假设** silver 和 gold 层 parquet 数据存在，**当** 研究者按股票和日期区间查询日线，**那么** 查询层只返回相关记录，并保持规范 schema。
2. **假设** manifest 和质量记录存在，**当** 研究者查询数据版本，**那么** 查询层返回构建状态、最新交易日和阻断检查摘要。
3. **假设** 本地数据继续增长，**当** 大规模 OHLCV 数据仍保存在 parquet 中，**那么** 元数据和运行状态仍可查询，而不需要把完整行情复制进传统行式数据库。

---

### 用户故事 4 - 区分源数据、清洗数据和策略可用数据 (优先级：P4)

作为系统维护者，我需要清晰的 raw/bronze/silver/gold 数据分层，让 QMT 和 AKShare 原始拉取结果被保留，清洗数据可以复现，策略输入只能在验证通过后被提升到可用层。

**为什么是这个优先级**：现有 `data/` 目录已经有很多有价值的产物，但研究输出、规范化数据、原始快照和质量报告之间的边界还不够严格；实盘前必须把这些边界理顺。

**独立测试方式**：可以把现有文件映射到规划中的数据层，并确认每个策略输入都有可追溯的上游来源。

**验收场景**：

1. **假设** 一次 QMT 或 AKShare 拉取完成，**当** 原始数据落盘，**那么** 它必须是不可变的，并包含数据源、快照时间和提取上下文。
2. **假设** 标准化数据从原始数据生成，**当** 它经过 bronze 和 silver 层，**那么** schema 标准化和清洗规则必须可审计。
3. **假设** 策略读取 gold 层输入，**当** 查看数据血缘，**那么** 可以定位源 raw 文件和验证检查结果。

## 范围边界

### MVP 范围

第一版只覆盖数据底座的“可运行骨架”：

- 定义 raw/bronze/silver/gold/manifest/quality/state 分层。
- 建立数据门禁规则和检查合同。
- 建立数据版本 manifest 合同。
- 建立 DuckDB 风格查询目录合同。
- 建立 SQLite 元数据边界。
- 完成现有 `data/` 文件到新分层的迁移映射。
- 为 PIT 目标表建立合同和优先级，但不要求第一版一次补全所有历史 PIT 数据。

### 非目标

- 不修改 QMT 硬编码凭证处理。
- 不实现真实订单、成交、持仓、资金流水账本。
- 不建立 ClickHouse、TimescaleDB 等服务端时序/列式数据库。
- 不承诺一次性补齐所有历史 PIT 数据。
- 不改变现有策略逻辑和交易逻辑。

## 数据门禁判定规则

### 运行模式

- **研究模式**：允许使用历史快照和部分近似数据，但必须显式提示局限。
- **回测模式**：必须通过行情完整性、复权一致性、股票池日期对齐和 manifest 校验。
- **模拟交易模式**：必须接近实盘要求，但允许部分非关键 AKShare 交叉校验降级为警告。
- **实盘模式**：所有阻断检查必须通过，否则不得生成实盘订单候选。

### 新鲜度规则

- 如果评估时间在交易日盘前或盘中，实盘模式允许最新行情日期等于上一交易日。
- 如果评估时间在交易日收盘后并且数据更新窗口已经结束，实盘模式要求最新行情日期等于当天交易日。
- 如果当天不是交易日，实盘模式要求最新行情日期等于最近一个交易日。
- 数据更新窗口的具体截止时间由后续实现配置；本 spec 默认以本地交易日历为准。

### 默认阈值

- 全 A 日线主数据覆盖率：实盘模式不低于 99.5%，回测模式不低于 99.0%。
- 后复权与未复权 `(股票, 日期)` 覆盖率：不低于 99.0%。
- 后复权与未复权成交额相对差异：超过 0.1% 的行数必须为 0，除非该股票被隔离。
- OHLC 关系错误：必须为 0。
- 必需字段空值：必须为 0。
- 股票日期重复行：必须为 0。
- QMT 与 AKShare 收盘价交叉校验：默认相对差异超过 0.5% 记为异常样本；是否阻断按数据集角色决定。
- gold 层 execution universe 最新日期：实盘和模拟交易模式必须覆盖最新允许交易日。

### 跨源校验阻断策略

- QMT 是日线、复权行情、交易日历、实盘行情和执行相关状态的主源。
- AKShare 是财务、流通股本、换手率和公开网页类数据的主源或补充源。
- 对实盘执行强相关的数据，QMT 主源失败必须阻断。
- AKShare 临时不可用时，若它只是交叉校验源，实盘模式默认警告；若它是该数据集主源，则按该数据集重要性决定是否阻断。
- 任一跨源差异不得静默覆盖主源数据；只能记录、隔离或人工确认。

## PIT 数据优先级

PIT（Point-in-Time，按当时可见信息取数）数据分阶段建设：

- **P0**：复权因子、公司行动、涨跌停状态、停复牌状态。它们直接影响收益、成交和可交易性。
- **P1**：历史 ST 状态、指数成分 PIT、行业成分 PIT。它们影响股票池和截面归属。
- **P2**：财报公告日、财务指标可用日期、股本变动可用日期。它们影响基本面因子和财务筛选。

第一版必须建立这些表的目标 schema 和数据源策略，但可以只先落地 P0/P1 中已有数据可支持的部分。

## 数据库边界

- **Parquet**：存储大规模行情、股票池、行业、财务、PIT 明细和策略输入数据。
- **DuckDB 或同类查询层**：提供 SQL 风格查询，不复制全量 parquet 数据。
- **SQLite**：第一阶段存储数据版本、质量结果、数据源覆盖结果、查询目录和运行元数据。
- **PostgreSQL**：当出现多进程写入、远程看板、多人协作或服务化部署任一需求时，再评估升级。
- **订单/成交/持仓/资金账本**：不属于本 spec 的 MVP，只预留未来 live state 边界。

## 边界情况

- QMT 数据可用但 AKShare 临时不可用；只有当对应数据集不强依赖 AKShare 阻断校验时，实盘就绪才允许通过。
- AKShare 对部分股票返回空财务数据；结果必须记录为数据源覆盖限制，不能静默丢弃。
- 本地最新交易日早于预期最新交易日；实盘模式必须阻断，研究模式可以警告。
- 某只股票只存在于 QMT 或只存在于 AKShare；覆盖缺口必须报告数量和示例。
- parquet 文件发生变化但没有生成新 manifest；任何使用该文件的运行都必须被视为不可复现，直到创建新的数据版本。
- 历史 PIT 字段不可用；受影响数据集必须标记为“基于当前快照”或“近似数据”。
- 按用户要求，QMT 凭证硬编码处理明确不属于本功能范围。

## 需求 *(必填)*

### 功能需求

- **FR-001**：系统必须定义本地数据分层架构，包括 raw、bronze、silver、gold、manifest、quality 和 state 区域。
- **FR-002**：系统必须保留原始数据源拉取结果，不能覆盖之前的原始拉取。
- **FR-003**：系统必须定义日线、后复权日线、可执行股票池、数据版本、质量检查、数据源覆盖率和运行元数据的规范 schema。
- **FR-004**：系统必须定义哪些数据集存为 parquet 文件，哪些记录进入元数据/状态数据库。
- **FR-005**：系统必须支持对大型 parquet 数据集进行 SQL 风格查询，且不要求把全量数据导入传统行式数据库。
- **FR-006**：系统必须定义数据版本 manifest，记录文件路径、哈希、行数、日期范围、数据源名称、质量结果和构建时间。
- **FR-007**：系统必须定义数据就绪门禁，并区分研究、回测、模拟交易和实盘模式。
- **FR-008**：系统必须定义阻断和警告检查项，覆盖数据过期、文件缺失、股票日期重复、OHLC 一致性、后复权/未复权一致性、可执行股票池新鲜度和跨源覆盖率。
- **FR-009**：系统必须定义 QMT 和 AKShare 在各类数据集上的“主数据源”和“交叉校验源”角色。
- **FR-010**：系统必须定义 PIT 目标表，包括公司行动、复权因子、涨跌停状态、停复牌状态、ST 状态、指数成分、行业成分和财报可用日期。
- **FR-011**：系统必须要求未来所有信号和回测运行元数据都且只能引用一个数据版本。
- **FR-012**：系统必须定义现有本地文件的迁移计划，且不能删除或重写原始数据。
- **FR-013**：系统必须记录 100G 本地空间预算下的容量预期。
- **FR-014**：系统必须明确说明 QMT 硬编码凭证移除不属于本功能范围。
- **FR-015**：系统必须定义 raw、bronze、silver、gold 各层的准入和准出规则。
- **FR-016**：系统必须定义实盘模式下数据新鲜度的盘前、盘中、盘后判定规则。
- **FR-017**：系统必须定义 SQLite 升级到 PostgreSQL 的触发条件。
- **FR-018**：系统必须明确订单、成交、持仓和资金账本不属于本 MVP。

### 关键实体 *(涉及数据时必填)*

- **数据源**：表示 QMT、AKShare 或未来数据提供方，以及它们在各类数据集上的角色。
- **原始数据快照**：不可变的数据源拉取结果，包含来源、快照时间、提取参数和文件引用。
- **规范数据集**：已经清洗或可供策略使用的数据集，具有稳定 schema 和明确分层。
- **数据版本**：不可变 manifest，用于把一组数据集和质量结果绑定成一个可复现的数据状态。
- **质量检查结果**：某条数据校验规则在某个数据集和运行模式下的结果。
- **数据源覆盖结果**：按数据集、日期范围和股票池记录跨源可用性与差异。
- **查询目录条目**：命名查询或视图，用于把 parquet 或元数据记录暴露给本地 SQL 风格访问。
- **运行元数据**：回测、信号、模拟交易或实盘运行记录，并绑定一个数据版本。

## 成功标准 *(必填)*

### 可衡量结果

- **SC-001**：评审者不需要阅读实现代码，就能识别哪些数据集继续以 parquet 存储，哪些记录进入元数据/状态数据库。
- **SC-002**：评审者能判断每类主要数据应以 QMT 还是 AKShare 作为主数据源。
- **SC-003**：规划中的数据就绪门禁至少覆盖 10 个具体检查项，并按运行模式区分阻断和警告。
- **SC-004**：规划数据模型包含把一次信号运行追溯到数据版本所需的全部实体。
- **SC-005**：`data/normalized`、`data/universe`、`data/sector`、`data/benchmark`、`data/akshare`、`data/manifest` 和 `data/quality` 下的现有文件都有明确迁移目标。
- **SC-006**：该计划允许本地系统在 100G 空间预算内支撑日频数据、财务数据和近期分钟级扩展。
- **SC-007**：实盘模式下每个阻断条件都有明确阈值或判定规则。
- **SC-008**：MVP 范围和非目标能让实现者判断哪些任务应推迟到后续 spec。

## 假设

- 大型行情数据继续以 parquet 为主存储；传统行式数据库只保存元数据、运行状态、审计日志和实盘状态。
- DuckDB 或同类嵌入式分析查询层将用于对 parquet 做 SQL 风格查询。
- SQLite 适合作为第一阶段本地元数据/状态存储；当需要多进程、远程访问、多人协作或服务化部署时，再升级到 PostgreSQL。
- ClickHouse 等列式服务端数据库推迟到分钟线、tick 或 Level2 数据规模真正需要时再考虑。
- QMT 是实盘交易、实时行情、历史 OHLCV 和执行相关状态的优先数据源。
- AKShare 是研究补充源和交叉校验源，尤其适合财务报表、流通股本、换手率和公开网页类数据。
- 本功能只做规划；本次 SDD 不创建实现代码、迁移脚本或运行时脚本。
