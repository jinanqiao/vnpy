# Phase 0 Research: 主线强势股策略回测

**Date**: 2026-07-08　全部 NEEDS CLARIFICATION 已在 spec 阶段由用户确认（后复权重下 / 次日开盘执行 / 等权），本文档落定实现层面的技术决策。

## R1: 复权方式与下载通道

**Decision**: 用现有 QMT 网关封装（`vnpy/alpha/research/qmt_gateway_data.py`）的 `adjust="back"`（后复权）下载全 A 日线，写入新文件 `data/normalized/daily_bars_all_a_adjusted.parquet`，schema 与未复权文件一致。

**Rationale**: 后复权价格的历史段不随未来分红改变（PIT 稳定，重跑可复现）；QMT 网关 `/market/bars/{symbol}` 已支持 `adjust` 参数透传，无需改网关。前复权每次分红都会重写全部历史价格，破坏"同输入同输出"承诺，排除。自算复权因子需要分红送转明细，QMT 网关当前无此接口，排除。

**实测风险（已解决）**: 2026-07-08 实测旧 IP `47.93.170.141:8710` 超时；用户确认公网 IP 已更换为 `8.141.119.179`，新 IP 健康检查通过、`adjust="back"` 行情拉取验证成功（招商银行未复权 37.94 vs 后复权 177.84，量级符合多年分红累积）。已更新 `qmt_gateway_data.py` 的默认 IP。注意：网关冷启动时首个行情请求可能超时，下载 CLI 需内置单只重试；阿里云公网 IP 可能再次变化，出现连接超时先找用户确认 IP，可用 `QMT_GATEWAY_URL` 环境变量覆盖。

## R2: 执行日与执行价

**Decision**: 执行日 = 信号日（月末）的次一交易日（按上交所日历推算）；执行价 = 执行日开盘价（后复权），买入加滑点、卖出减滑点。执行日个股无行情（停牌）或一字板：买入放弃、卖出顺延到下一个可交易日，均记录。

**Rationale**: 信号用月末收盘数据算出，最早能行动的时点就是次日开盘——这是无未来信息的最紧执行假设（用户确认方案 A）。一字板判定用日线近似：`high == low` 且相对前收上涨（一字涨停，买不进）/下跌（一字跌停，卖不出），局限写入报告（盘中打开的涨跌停无法用日线识别，回测略保守）。

## R3: 记账模型——份额 + 复权收益演化

**Decision**: 每笔持仓记录"真实股数 + 投入金额 + 买入日后复权价"三元组：
- 真实股数用**未复权**执行价按 100 股整手向下取整（真实交易约束）；
- 此后逐日市值 = 投入金额 × (当日后复权收盘 / 买入日后复权开盘)（收益演化）；
- 卖出金额 = 卖出执行日按后复权开盘演化的市值，扣印花税/佣金/滑点。

**Rationale**: 直接"股数 × 未复权价"估值会把除权跳空当亏损；直接在后复权价格空间算股数则整手约束失真。份额演化模型两头兼顾，且对初学者直观（"这笔钱涨到了多少"）。隐含假设：分红自动再投资（后复权收益天然涵盖），写入报告固定声明。

**Alternatives considered**: 显式分红现金流建模——需要分红明细数据（无接口）且复杂度大增，拒绝。

## R4: 成本模型

**Decision**: 三项独立记账、全部可配置：佣金（默认双边 0.025%）、印花税（默认卖出 0.05%）、滑点（默认单边 0.1%，直接调整执行价）。回测同时维护一个"零成本影子账户"（同样的交易序列、成本置零），一次运行同时产出含成本/零成本两条净值（SC-006 成本拖累）。

**Rationale**: 影子账户只是并行累乘两组收益，实现成本极低，避免用户跑两次再对齐。

## R5: 基准与对比

**Decision**: 基准用 `data/benchmark/index_daily.parquet` 中的 `000300.SH`（沪深300）收盘价，归一到回测起点。报告给出：组合净值、基准净值、超额净值（组合/基准）、分年度对比。

**Rationale**: 数据已在湖中（2021-05 ~ 2026-07 全覆盖，实测确认），价格指数口径已在 spec Assumptions 声明。

## R6: 指标定义（写死在 metrics 模块 docstring，避免口径争议）

| 指标 | 定义 |
|---|---|
| 年化收益 | (期末净值)^(252/交易日数) - 1 |
| 最大回撤 | min(净值/历史峰值 - 1) |
| 夏普比率 | 日收益均值 / 日收益标准差 × √252（无风险利率取 0） |
| 月度胜率 | 调仓期间组合收益 > 0 的期数占比；另报"跑赢基准胜率" |
| 年均换手率 | Σ每期买入金额 / 期初净值，按年折算 |
| 成本拖累 | 零成本年化 - 含成本年化 |

## R7: 停牌与退市的估值处理

**Decision**: 持仓停牌期间按最后可得后复权价冻结市值；停牌超过 20 个交易日在报告中单列；数据中此后再无行情的个股（疑似退市）在最后可得价格日按该价格强制清仓（收印花税佣金，不收滑点），记入交易流水 `status=forced`。

**Rationale**: 冻结估值是无日内数据下最中性的假设；强制清仓避免"僵尸持仓"永久占用净值。

## R8: 新旧行情一致性校验（FR-011a）

**Decision**: 下载完成后自动校验三项，结果写入数据质量报告：
1. 覆盖率：后复权文件的 (symbol, date) 对 ≥ 未复权文件的 99%；
2. 成交额一致：同 (symbol, date) 的 turnover 相对差 < 0.1%（复权不改成交额）；
3. 复权比例阶梯性：`adj_close/unadj_close` 逐日变化 > 0.1% 的日期即除权日，每只股票的除权日数量应在合理量级（≤ 20 次/5 年），比例只升不降（后复权特性）。

## R9: 下载策略（全 A 约 5200 只）

**Decision**: 分批下载（默认每批 200 只），每批写 `data/raw/qmt/adjusted/` 下的分片 parquet；全部批次完成后合并、校验、原子写入最终文件；`--resume` 跳过已存在分片；失败股票记入 `failed_symbols_adjusted.json` 支持单独重试。参考 turtle 下载脚本的成熟模式（逐只 try/except + 失败清单）。

**Rationale**: 5200 只 × 逐只 HTTP 请求预计 30~60 分钟，必须可断点续传；不完整数据绝不写入最终路径（spec US4-AS2）。
