# Feature Specification: 主线强势股策略回测

**Feature Branch**: `002-mainline-backtest`

**Created**: 2026-07-08

**Status**: Draft

**Input**: User description: "帮我设计这个策略的回测计划。我该怎么回测，回测需要哪些数据。有不确定的找我确认"

## 背景

001 特性已交付信号生成：每个月末产出主线行业与入选个股清单（`selection.parquet`），但"这个策略历史上到底赚不赚钱、风险多大"尚无答案。本特性把信号清单变成可度量的历史业绩：模拟按清单逐月调仓的真实交易过程，产出净值曲线、风险指标和与基准的对比。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 跑通全历史回测，看到策略的真实成绩单 (Priority: P1)

研究者用一条命令对 001 产出的信号清单执行全历史回测（约 2022-03 至今，50+ 个调仓期），得到净值曲线、核心风险收益指标（总收益、年化、最大回撤、夏普、月度胜率）以及与沪深300 基准的对比，从而判断策略是否值得继续投入。

**Why this priority**: 这是回测的根本目的——没有业绩答案，信号系统只是一堆表格。

**Independent Test**: 用 001 的真实信号产物跑一次全历史回测，检查产物齐备、指标数值合理（净值可独立复算）、报告含基准对比。

**Acceptance Scenarios**:

1. **Given** 001 已产出的全历史 `selection.parquet`，**When** 执行回测命令，**Then** 产出净值曲线、指标汇总与图文报告，退出码 0
2. **Given** 回测产物，**When** 用持仓明细和行情价格手工复算任意一天的组合净值，**Then** 与产物中的净值一致（误差 < 0.01%）
3. **Given** 信号清单中某期为空仓（无主线行业），**When** 回测经过该期，**Then** 组合全额持有现金，净值曲线平直
4. **Given** 同样的信号与参数，**When** 回测运行两次，**Then** 结果完全一致

---

### User Story 2 - 每笔交易可追溯，异常处理透明 (Priority: P2)

研究者能查到回测中每一笔买入/卖出的执行日期、价格、数量、各项成本，以及所有"计划交易但未能成交"的记录（停牌卖不出、执行日不可交易放弃买入等），确认回测没有偷偷用到未来信息或忽略交易约束。

**Why this priority**: 回测最大的风险是"结果好看但不可信"。交易明细是检验回测可信度的唯一入口。

**Acceptance Scenarios**:

1. **Given** 回测产物中的交易流水，**When** 抽查任意一笔交易，**Then** 能看到信号来源期、执行日、执行价、数量、佣金/印花税/滑点各项金额
2. **Given** 某入选个股在执行日停牌，**When** 回测处理该期调仓，**Then** 该笔买入被放弃并记录原因，资金留存为现金
3. **Given** 某持仓个股在调仓卖出日停牌或一字跌停，**When** 回测处理卖出，**Then** 延迟到下一个可交易日执行并记录延迟天数

---

### User Story 3 - 参数对照实验 (Priority: P3)

研究者可以修改成本假设、权重方案等回测参数跑对照实验（例如零成本 vs 含成本、等权 vs 得分加权），对比多次运行的指标，评估策略对假设的敏感程度。

**Why this priority**: 敏感性分析决定结论的稳健性，但先要有单次可信的回测。

**Acceptance Scenarios**:

1. **Given** 两次不同成本假设的回测，**When** 对比产物指标，**Then** 参数差异记录在各自的配置快照中，指标差异可归因
2. **Given** 报告产物，**When** 查看成本影响段落，**Then** 能看到零成本与含成本两条净值的对比

---

### User Story 4 - 数据湖升级：后复权行情 (Priority: P1，US1 的前置)

研究者需要一份不受分红除权干扰的价格序列来计算真实收益。系统从 QMT（阿里云实例已启动）重新下载全 A 后复权日线，落入数据湖为新文件，原有未复权数据保持不动。下载后自动校验数据质量（覆盖范围、与未复权数据的一致性），校验通过后回测才使用。

**Why this priority**: 未复权价格会把每次分红除权当成真实亏损，直接扭曲回测结论；这是回测可信的前提。

**Independent Test**: 独立运行数据下载命令，检查新文件覆盖的股票数与日期范围不低于现有未复权数据的 99%，抽样个股在除权日附近复权价连续无跳空。

**Acceptance Scenarios**:

1. **Given** 阿里云 QMT 实例已启动，**When** 执行数据下载命令，**Then** 数据湖新增全 A 后复权日线文件，覆盖范围与现有数据相当，校验报告生成
2. **Given** QMT 连接失败，**When** 下载中断，**Then** 给出明确错误信息与失败清单，不写入不完整文件（用户协助补数据后可重跑）
3. **Given** 新旧两份行情，**When** 对比同一股票同一交易日，**Then** 除权日之外复权价/未复权价的比例恒定，成交额一致

---

### Edge Cases

- 某期空仓（无主线行业）：全额现金，不计利息
- 执行日个股停牌/一字涨停：放弃买入，记录原因
- 持仓个股停牌跨越调仓日：延迟卖出至可交易日；若长期停牌（>20 个交易日）按最后价格冻结估值并在报告标注
- 除权日价格跳空：改用后复权行情后自然消除；新增数据校验（FR-011a）兜底
- 持仓个股退市/长期无后续行情：以最后可得价格清仓并记录
- 资金取整：A 股按 100 股整数手买入，剩余零钱留存现金
- 单期入选数量很少（如 1 只）：按权重方案正常执行，不强制分散
- 回测起点前几期信号窗口不足（001 已跳过）：回测从第一个有效信号期开始

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统 MUST 读取 001 产物 `selection.parquet` 作为唯一的调仓信号来源，不得在回测内重算信号
- **FR-002**: 系统 MUST 以信号日的次一交易日为执行日、以执行日开盘价为基准执行价（叠加滑点），确保信号计算与交易执行之间无未来信息（用户已确认）
- **FR-003**: 系统 MUST 按"全部入选个股等权"计算目标持仓权重（用户已确认；行业等权、score 加权留作后续对照实验的可配置扩展）
- **FR-004**: 系统 MUST 对每笔交易计入可配置的交易成本：佣金（默认双边 0.025%）、印花税（默认卖出 0.05%）、滑点（默认单边 0.1%），并单独记账
- **FR-005**: 系统 MUST 处理卖出受阻：执行日停牌或一字跌停的持仓延迟到下一个可交易日卖出，并记录延迟
- **FR-006**: 系统 MUST 处理买入受阻：执行日不可交易的信号个股放弃买入并记录原因，资金留存现金
- **FR-007**: 系统 MUST 在空仓期全额持有现金（不计利息），净值曲线连续
- **FR-008**: 系统 MUST 计算并报告与沪深300 基准的对比：超额收益、相对净值曲线
- **FR-009**: 系统 MUST 输出核心指标：总收益、年化收益、最大回撤、夏普比率、月度胜率、年均换手率、成本拖累（零成本与含成本的年化差）
- **FR-010**: 系统 MUST 按年度分段统计收益与回撤，识别策略在不同市场环境下的表现
- **FR-011**: 系统 MUST 使用后复权行情做收益计算与估值：本特性包含一个数据湖升级子任务，用 QMT（用户的阿里云实例已启动）重新下载全 A 后复权日线并落入数据湖新文件；未复权行情仅保留用于可交易性等原有用途（用户已确认方案 A）
- **FR-011a**: 数据升级 MUST 校验新旧行情的一致性（同一交易日成交额一致、复权价与未复权价的比例在除权日之外恒定），校验结果记入数据质量报告
- **FR-012**: 系统 MUST 留档全部产物（配置快照、净值序列、逐日持仓、交易流水、指标汇总、图文报告），同输入重跑结果完全一致
- **FR-013**: 回测参数（初始资金、成本率、权重方案等）MUST 全部可配置且记录在配置快照中

### Key Entities

- **回测配置**: 初始资金、执行时点规则、权重方案、成本率、回测区间；一次运行的完整参数快照
- **交易流水**: 每笔已成交/被放弃/被延迟的交易，含信号来源期、执行日、价格、数量、成本分项、状态与原因
- **逐日持仓**: 每个交易日每只持仓的数量、市值、权重，加现金余额
- **净值序列**: 逐日组合净值、基准净值、超额净值
- **指标汇总**: FR-009/FR-010 全部指标，含分年度分段

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 一条命令完成全历史（50+ 期）回测，总耗时 ≤ 5 分钟，产物六件套齐备
- **SC-002**: 任意一天的组合净值可用逐日持仓与行情独立复算，误差 < 0.01%
- **SC-003**: 任意一笔交易可追溯到信号来源期与成本分项，抽查 10 笔无一例外
- **SC-004**: 同输入重跑两次，全部数值产物逐字节一致
- **SC-005**: 报告包含与沪深300 的对比及分年度统计，非专业读者能在 5 分钟内看懂策略历史表现
- **SC-006**: 报告呈现零成本与含成本两组结果，成本拖累可量化

## Assumptions

- 初始资金默认 100 万元人民币（可配置），单一账户全仓运作
- A 股交易约束：按 100 股整数手成交，T+1（当月买入的股票下月调仓才卖出，天然满足）
- 佣金不建模"单笔最低 5 元"（组合金额下影响可忽略），印花税按现行卖出 0.05%
- 现金不计利息，不考虑打新、融资融券等收益增强
- 月中不做任何风控干预（止损、止盈留待后续特性），持仓原样保留到下一调仓期
- 基准使用沪深300 指数（`index_daily.parquet` 已含），不含分红的价格指数口径
- 阿里云 QMT 实例由用户维护且已启动；若下载过程连接失败或数据缺口，由用户协助补充后重跑下载命令
- 回测复用 001 的自包含代码风格约束（独立子包、polars、函数式、中文注释），具体在 plan 阶段确认
