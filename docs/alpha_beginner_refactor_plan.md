# Alpha System Refactor Plan for Beginners

这份文档面向两件事：

1. 把当前 Alpha/量化系统改造成更可信、更容易读懂、更容易维护的研究系统。
2. 让刚入门量化和 Python 的同学，能在面试中讲清楚：我做了什么、为什么这么做、怎么验证没有骗自己。

本文不追求一步到位做成机构级平台。第一目标是清晰、可验证、能解释。

## 0. 当前系统一句话定位

当前项目底层交易框架较完整，`vnpy.alpha` 已经有数据、因子、模型、信号、回测和策略模板。

真正要补的是：

- 研究流程更清晰
- 数据检查更显式
- 回测假设更真实
- 指标报告更完整
- 代码更适合学习和面试讲解
- 测试覆盖关键路径

## 1. 改造总原则

### 原则一：先让人读懂，再追求强大

每个模块只做一件事：

- `data`: 读数据、检查数据、整理字段
- `features`: 算指标和因子
- `signals`: 把因子变成买卖信号
- `portfolio`: 把信号变成目标持仓
- `backtest`: 模拟成交和计算每日盈亏
- `metrics`: 计算收益、回撤、夏普、换手等指标
- `report`: 输出表格、图和文字结论

### 原则二：每个回测假设必须写出来

面试时不能只说“我做了一个回测”，要能说清楚：

- 信号什么时候产生
- 交易什么时候发生
- 用什么价格成交
- 手续费和滑点怎么扣
- 有没有涨跌停、停牌、流动性限制
- 和什么基准比较

### 原则三：先做日频、简单、多检查

对初学者，先不要一上来追求分钟级、高频、复杂撮合。

推荐第一阶段统一使用日频逻辑：

- 第 t 日收盘后产生信号
- 第 t+1 日开盘或收盘调仓
- 第 t+1 日之后开始赚取收益

关键点是避免未来函数。

## 3. 分阶段改造路线

## Phase 1：先补数据检查层

目标：任何数据进入因子、模型、回测之前，都先过一遍体检。

新增模块建议：`vnpy/alpha/research/data_check.py`

要检查：

- 必要字段是否存在：`datetime`, `vt_symbol`, `open`, `high`, `low`, `close`, `volume`
- 时间是否排序
- 同一个标的同一天是否重复
- 价格是否小于等于 0
- `high >= low` 是否成立
- `open/close` 是否落在 `high/low` 区间内
- 缺失值数量
- 每个标的数据起止日期

面试讲法：

> 我先补了数据质量检查层，因为量化系统里很多问题不是模型错，而是数据口径、缺失值、重复日期、停牌和异常价格导致的。数据检查可以在策略运行前暴露问题，而不是等回测结果异常后再猜。

完成标准：

- 能对一个 DataFrame 输出一份数据质量摘要
- 异常数据能给出清晰错误信息
- 有 2 到 3 个单元测试覆盖重复日期、缺字段、异常价格

## Phase 2：补一个最小可解释回测器

目标：做一个比现有框架更简单、更适合学习的日频回测版本。

新增模块建议：`vnpy/alpha/research/simple_backtest.py`

第一版只支持：

- 日频
- 多股票
- long-only
- 信号日收盘后生成
- 下一交易日调仓
- 简单手续费
- 简单滑点
- 等权或按信号排序取 Top N

核心公式：

```python
position_today = signal_yesterday
strategy_return = position_today * asset_return_today - turnover_today * cost_rate
equity = (1 + strategy_return).cumprod()
```

最重要的一行是 `shift(1)`：信号要滞后一日才能参与收益计算。

面试讲法：

> 我先实现了一个最小日频回测器，不是为了替代完整撮合引擎，而是为了把信号、持仓、收益、换手、成本这条链路讲清楚。尤其是通过 `shift(1)` 避免今天收盘信号直接赚今天收益的未来函数问题。

完成标准：

- 输入价格和信号，输出每日收益、净值、换手
- 有无成本两条曲线
- 有单元测试证明 `shift(1)` 生效

## Phase 3：补指标和审计报告

目标：不要只看收益率，要看风险和稳定性。

新增模块建议：`vnpy/alpha/research/metrics.py`

第一版指标：

- 总收益
- 年化收益
- 年化波动
- Sharpe
- 最大回撤
- Calmar
- 胜率
- 平均换手
- 最大单日亏损
- 基准收益
- 超额收益

第二版指标：

- Sortino
- 月度收益表
- 滚动 60 日 Sharpe
- 滚动最大回撤
- 分年度表现
- 成本前后对比

面试讲法：

> 我没有只看最终收益，而是补了最大回撤、夏普、Calmar、换手和成本前后对比。因为量化策略的核心不是某段时间赚了多少，而是收益是否稳定、回撤是否可承受、收益是否被交易成本吃掉。

完成标准：

- 任意一条收益序列都能生成指标字典
- 指标函数有单元测试
- 回测报告中同时展示成本前和成本后表现

## Phase 4：补真实交易约束

目标：让回测逐步接近实盘。

需要补的约束：

- 单票最大权重
- 最大持仓数量
- 最大日换手
- 最小成交金额
- 停牌不可交易
- 涨停不可买
- 跌停不可卖
- 成交量限制，例如不超过当日成交额的 5%
- 手续费、印花税、滑点分开配置

面试讲法：

> 我把回测从理想成交改成带交易约束的版本。比如涨停不能买、跌停不能卖、单日成交不能超过成交额的一定比例。这些限制会降低回测收益，但能减少纸面收益和真实交易之间的差距。

完成标准：

- 每个约束都能通过配置开关控制
- 回测结果能统计“有多少订单因为限制没有成交”
- 测试覆盖涨停不可买、跌停不可卖、成交量限制

## Phase 5：补实验追踪

目标：每次研究都能复现。

新增模块建议：`vnpy/alpha/research/experiment.py`

每次回测保存：

- 实验名称
- 代码版本
- 数据路径
- 交易品种池
- 起止日期
- 因子名称
- 模型参数
- 回测参数
- 成本参数
- 指标结果
- 输出文件路径

推荐保存成 JSON，而不是只靠 pickle。

面试讲法：

> 我补了实验追踪，每次回测都会记录数据版本、参数、时间区间、成本假设和指标结果。这样策略表现变化时可以追溯原因，也方便复现实验。

完成标准：

- 每次运行生成一个 `experiments/<timestamp>/config.json`
- 指标结果保存为 `metrics.json`
- 净值曲线保存为 `equity.csv`

## Phase 6：再优化现有 BacktestingEngine

等前面简单链路跑通后，再回到当前的 `vnpy/alpha/strategy/backtesting.py` 做增强。

优先增强点：

- 成交模型拆出来，不要全部写在 `cross_order`
- 成本模型拆出来
- 风控检查拆出来
- 指标计算拆出来
- 日志更结构化
- 回测结果对象更清晰

建议拆成：

```text
execution.py      # 撮合和成交
cost.py           # 手续费、印花税、滑点
risk.py           # 仓位和交易限制
accounting.py     # 现金、持仓、市值、盈亏
statistics.py     # 指标
```

面试讲法：

> 我先用简单回测器验证核心逻辑，再反向改造原有引擎。这样不是盲目重构，而是先建立一个正确、可测试、可解释的参考实现，再逐步把复杂引擎模块化。

## 5. 面试讲解模板

可以按这个顺序讲：

### 1. 项目背景

> 这个项目基于 vn.py/VeighNa，我重点改造的是 Alpha 研究到回测的链路，包括数据检查、信号生成、持仓构建、交易成本、回测指标和实验追踪。

### 2. 为什么要改

> 原系统功能比较完整，但对初学者和面试展示来说，核心链路不够显式。比如数据质量、未来函数、交易成本、回测假设和实验复现都需要更清楚地暴露出来。

### 3. 怎么改

> 我没有一上来大重构，而是先新增一个教学型 research 子模块，把数据、因子、信号、组合、回测、指标、报告拆开。每个模块都小而清晰，并且补关键单元测试。

### 4. 最重要的量化问题

> 我重点防了三类问题：未来函数、忽略交易成本、回测成交过于理想。比如信号必须 `shift(1)` 后才能参与收益计算；成本前后指标要同时展示；涨跌停和成交量限制会影响实际可成交性。

### 5. 结果怎么验证

> 我会看总收益、年化收益、夏普、最大回撤、Calmar、换手、成本前后差异、基准对比，还会做不同时间区间和不同成本假设下的鲁棒性测试。

## 6. 推荐实施顺序

不要同时开太多战线。建议顺序：

1. 新增 `data_check.py`
2. 新增 `metrics.py`
3. 新增 `simple_backtest.py`
4. 给这三个模块补单元测试
5. 新增一份 `alpha_research_workflow.md`
6. 新增实验追踪
7. 再反向改造原 `BacktestingEngine`

## 7. 第一批代码的设计要求

第一批代码必须满足：

- 函数名直观
- 每个函数不超过大约 40 行
- 参数尽量显式
- 不引入复杂继承
- 不用过度抽象
- 错误信息要能让初学者看懂
- 每个模块顶部写清楚输入和输出

示例函数名：

```python
check_price_data(df)
calculate_returns(df)
build_top_n_weights(signal_df, top_n=50)
calculate_turnover(weights)
apply_transaction_costs(returns, turnover, cost_rate)
calculate_max_drawdown(equity)
summarize_performance(returns)
```

## 8. 暂时不要做的事

这些不是没用，而是不适合第一阶段：

- 分布式计算
- 高频撮合
- 深度学习模型调参
- 复杂风险模型
- 过早封装大型类继承体系
- 过早接实盘资金

先把“数据可信、回测可信、指标可信、解释可信”做好。
